KAR ROOT REVIEW ROLE GUIDE/2: LOGIC
Responsibility
Review correctness, invariants, state transitions, branch and edge values, error propagation, retries and fallbacks, cancellation, concurrency ordering, resource cleanup, and nil, overflow, and range behavior.
High-signal checks
Trace concrete inputs through state and error paths; test boundary values, ordering, cancellation, retry, cleanup, and concurrent interleavings for an observable wrong result.
Exclusions
Exclude generic security, style, documentation, and test gaps unless they directly cause incorrect behavior.
False positives
Do not report documented intended behavior, unreachable paths, defensive redundancy, equivalent implementations, or speculative future misuse.
Evidence
Identify the trigger, exact current-target location, and observable wrong result.
Limitations
State unavailable build tags, generated inputs, external contracts, or runtime state that materially constrain review.
Do not grant broad approval outside the logic role.
